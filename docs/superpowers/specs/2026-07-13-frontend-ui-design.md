# 智能简历生成工具：前端 UI 设计稿

> 日期：2026-07-13  
> 范围：登录、简历库、编辑器、模板、头像、PDF 导出、AI 点评  
> 性质：视觉与交互设计；不包含前端实现方案

## 1. 设计命题

**产品对象**：正在求职、需要把零散经历整理成专业简历的中文用户。  
**核心任务**：让用户从“我不知道怎样写”进入“我清楚下一步改什么、可以放心投递”。

界面采用“**职业档案夹**（Career Dossier）”作为统一隐喻：工作区是安静的浅灰蓝桌面，简历是清晰的 A4 纸张，编辑模块像档案夹边缘的分类标签。它用真实的求职物件建立信任感，而不是使用常见的渐变 SaaS 仪表盘。

## 2. 视觉系统

| 设计令牌 | 值 | 用途 |
|---|---:|---|
| Ink Navy | `#15243A` | 主标题、深色导航、正文重点 |
| Archive Blue | `#2962FF` | 主操作、选中标签、焦点环 |
| Paper White | `#FCFCFA` | A4 简历与主内容表面 |
| Desk Mist | `#EEF2F7` | 应用背景、编辑画布 |
| Signal Coral | `#F26A5A` | 待处理提示、删除等风险操作 |
| Evidence Green | `#27866F` | 已保存、完成、正向进度 |

- **标题字体**：`Noto Sans SC` SemiBold；大标题字紧、留白充足，避免花哨的展示字体。
- **正文**：`Noto Sans SC` Regular；14–16px，行高 1.6。
- **数据与状态**：`DM Mono` / 等宽回退字体；用于“已保存”“上次修改”“82/100”等信息，形成专业档案感。
- **圆角与阴影**：页面结构使用 8px 圆角；A4 纸张只用 2px 圆角；阴影低对比度、不漂浮。

### 标志性元素：档案标签脊

编辑器左侧不使用普通垂直菜单，而是使用一条 36px 宽的**蓝色档案夹标签脊**。每一项是有明确内容意义的纵向标签：基本信息、教育、项目、工作、技能、补充。选中项向内容区展开，未完成项显示一个细小的珊瑚色缺口。这一元素只出现在编辑场景，既表达内容结构，也让产品具有识别度。

## 3. 页面设计

### 3.1 登录 / 注册

页面不是传统的居中卡片。1440px 桌面端采用 5:7 的双栏：左侧是深蓝档案封面，右侧是纸白登录面。

```
┌──────────────────────── 1440 px ────────────────────────┐
│  深蓝档案封面（42%）             纸白登录区（58%）       │
│  Resume / 01                    欢迎回来                 │
│  把经历，整理成机会。            手机号或邮箱             │
│  一张微缩 A4 简历 + 蓝色标签     密码                     │
│  “从第一条经历开始”              [登录]                  │
│                                  ─── 或 ───              │
│                                  [以游客身份体验]         │
└─────────────────────────────────────────────────────────┘
```

- 登录、注册以文字切换，不使用大面积 Tab 容器。
- 游客入口是次级描边按钮，并明确提示“可创建临时简历，随时注册保存”。
- 表单错误贴近字段显示，说明具体修复动作，例如“请输入 6–32 位密码”。

### 3.2 简历库（我的简历）

简历库是用户每天回来的工作台，强调“最近工作”和“下一步”。

```
┌──────┬───────────────────────────────────────────────────┐
│ 标志 │ 我的简历                          + 新建简历       │
│ 简历 │ ───────────────────────────────────────────────── │
│ 模板 │ [最近编辑]   [全部简历]             搜索           │
│ 头像 │ ┌──────────────┐ ┌──────────────┐  ┌────────────┐ │
│ 账户 │ │ A4 预览       │ │ A4 预览       │  │ 求职准备度 │ │
│      │ │ 前端工程师    │ │ 产品实习生    │  │ 72 / 100   │ │
│      │ │ 已保存 · 今天 │ │ 3 天前        │  │ 补全项目…  │ │
│      │ └──────────────┘ └──────────────┘  └────────────┘ │
└──────┴───────────────────────────────────────────────────┘
```

- 左侧导航仅保留真正的工作入口：简历、模板、头像、账户；当前项使用蓝色标签片，而非整块填色。
- 简历卡正面是可辨识的 A4 缩略图，信息放在纸张下方；悬浮后才显示复制、重命名、删除，减少噪声。
- 空状态是一张未填写的 A4 纸和“从一份简历开始”，主操作为“新建简历”，不出现空洞插画。

### 3.3 编辑器（核心界面）

编辑器把“填写”和“结果”放在同一视线内；桌面端比例为 `440px / 1fr / 320px`。

```
┌──────────────── 顶栏：简历名称 · 已保存 · 预览 · 导出 PDF ────────────────┐
│ 标签脊 │ 结构化编辑区                    │ A4 实时预览      │ AI 点评       │
│ 基本   │ 姓名 / 求职意向 / 联系方式       │                  │ 82 / 100      │
│ 教育   │ [可编辑字段]                     │   简历纸张       │ 先完善项目…   │
│ 项目   │ + 添加经历                       │                  │ 3 条建议      │
│ 工作   │                                  │                  │ [查看详情]    │
│ 技能   │                                  │                  │              │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 顶栏左侧为返回简历库、当前简历标题和编辑状态；“已保存”使用等宽小字 + 绿色圆点。
- 左侧表单一次只展开一个模块，保存用户的上下文；模块内部是分组字段与可复制的经历卡片。
- 中部 A4 预览始终为视觉主角：缩放、页数及模板信息浮在纸张下方，不覆盖内容。
- AI 点评默认收起为右侧 56px 的分数条；用户展开后才占据 320px 侧栏，避免编辑时分散注意。
- “导出 PDF”位于最右且始终可见；导出前若有必填缺失，按钮保留可点击并展示清晰的修复清单。

### 3.4 模板、头像、导出与 AI 点评

- **模板选择**：从编辑器右侧滑出，不跳转页面。每张模板卡包含 A4 缩略图、适用场景、信息密度标签；切换时预览纸张轻微交叉淡入。
- **头像流程**：先裁剪，再选白/蓝/红底与职业风格，最后显示任务进度。优化结果以“前后对照纸片”出现；用户明确选择“应用到本份简历”。
- **PDF 导出**：使用居中确认面板，展示文件名、页数、模板与“导出后可在下载中心获取”；避免把任务状态藏在 Toast 中。
- **AI 点评**：详情按“最值得先改 / 可增强 / 已做得好”排序。分数不是唯一主角，首屏必须显示可执行建议，例如“在项目经历中补充量化结果”。

## 4. 响应式与无障碍

- **≥ 1200px**：三栏编辑器，预览与 AI 点评可同时显示。
- **768–1199px**：隐藏 AI 栏为抽屉；表单和预览为两栏。
- **< 768px**：编辑、预览、点评改为底部三项切换；A4 预览按宽度缩放，所有主操作保留在底部安全区上方。
- 键盘焦点使用 2px Archive Blue 外环；所有状态不用颜色单独表达；减少动态效果时关闭纸张切换和侧栏滑动动画。

## 5. 交互语气与关键状态

| 场景 | 界面文案 |
|---|---|
| 自动保存中 | “正在保存” |
| 保存成功 | “已保存 · 刚刚” |
| 保存失败 | “未能保存。请检查网络后重试。” |
| 无简历 | “先建立一份简历，再慢慢补全它。” |
| AI 点评不可用 | “暂时无法生成点评；你的简历内容不会丢失。” |
| 导出完成 | “PDF 已生成，可以下载了。” |

## 6. 自检结论

- 设计没有使用项目无关的通用渐变、玻璃拟态或夸张数据大屏。
- 档案标签脊仅服务于“简历内容模块”的真实层级，不是装饰性编号。
- 三个最核心的用户问题——从哪里开始、当前有没有保存、下一步改什么——在简历库和编辑器中均有明确答案。
- 当前设计稿刻意不定义接口、组件拆分或实现细节，后续开发需要另行制定实现计划。
