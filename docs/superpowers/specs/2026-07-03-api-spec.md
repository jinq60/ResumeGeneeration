# 简历生成工具 API 规范

> 版本：v1.5
> 日期：2026-08-06
> 基于：`docs/superpowers/specs/2026-07-03-scope-alignment.md`、`docs/superpowers/specs/2026-07-03-data-model-and-ddl.md`、`docs/superpowers/specs/2026-07-03-validation-rules.md`

---

## 1. 概述

本文档定义智能简历生成工具当前版本 REST API 的接口契约，作为前后端开发、接口测试（TDD）和联调的主要依据；历史变更见 `docs/api-changelog.md`。

### 1.1 设计原则

1. **RESTful 资源路径**：使用复数名词表示资源集合。
2. **统一响应格式**：所有接口返回 `R<T>` 结构。
3. **JWT 认证**：除认证接口、健康检查、公开模板和公开分享页外，其余接口需在 `Authorization` Header 中携带 `Bearer {accessToken}`；`/admin/**` 还需管理员角色。
4. **游客模式兼容**：游客拥有临时 `userId` 与 Token，数据隔离策略与正式用户一致。
5. **幂等性**：创建类接口建议前端生成唯一请求 ID，后端对同一请求 ID 返回同一结果。

### 1.2 基础信息

- **Base URL**：`http://localhost:8080/api`（开发环境）
- **协议**：HTTPS（生产环境）
- **Content-Type**：`application/json`（文件上传除外）
- **字符编码**：UTF-8

```json
  "data": { }
```

### 2.2 失败响应

```json
{
  "code": 400,
  "message": "请求参数不正确，请检查。",
  "data": null
}
```

### 2.3 HTTP 状态码与业务码关系

| HTTP 状态码 | 业务码范围 | 含义 |
|---|---|---|
| 200 | 200 | 请求成功 |
| 400 | 400 / 1xxx | 参数校验失败 |
| 401 | 401 / 2xxx | 未认证或 Token 过期 |
| 403 | 403 / 3xxx | 无权限访问 |
| 404 | 404 / 4xxx | 资源不存在 |
| 409 | 409 / 5xxx | 资源冲突 |
| 429 | 429 / 6xxx | 请求过于频繁 |
| 500 | 500 / 9xxx | 服务器内部错误 |

## 3. 认证方式

所有受保护接口需在请求头中携带：

```http
Authorization: Bearer {accessToken}
```

当 Access Token 过期时，使用 Refresh Token 换取新的 Access Token。

## 5. 认证模块 `/auth`

### 5.1 注册账号

**POST** `/auth/register`

#### 请求体

```json
{
  "phone": "13800000000",
  "email": "zhangsan@example.com",
  "verifyCode": "123456",
  "password": "******"
}
```

#### 字段说明

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `phone` | string | 条件 | 与 `email` 至少填一个；格式 `^1[3-9]\d{9}$` |
| `email` | string | 条件 | 与 `phone` 至少填一个；标准邮箱格式 |
| `verifyCode` | string | 是 | 6 位数字 |
| `password` | string | 是 | 6–32 位 |

#### 成功响应

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "userId": "user_1720000000001",
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 3600
  }
}
```

#### 错误码

| 错误码 | 提示文案 |
|---|---|
| `AUTH_PHONE_REGISTERED` | 该手机号已注册。 |
| `AUTH_EMAIL_REGISTERED` | 该邮箱已注册。 |
| `AUTH_VERIFY_CODE_INVALID` | 验证码不正确或已过期。 |
| `AUTH_PASSWORD_TOO_WEAK` | 密码强度不足，请设置 6–32 位密码。 |

### 5.5 多方式登录适配器（v1.9）

#### 统一登录入口

**POST** `/auth/login/{method}`

`method` 支持 `password` / `email_code` / `sms_code`（预留，未开放）。请求体为键值对 JSON：

- `password`：`{"account": "手机号或邮箱", "password": "..."}`
- `email_code`：`{"email": "...", "code": "6 位验证码"}`

**GET** `/auth/methods`

返回可用登录方式与第三方配置状态（`configured` 布尔），前端据此渲染入口。

#### 邮箱验证码登录

**POST** `/auth/email-code/send`（`{"email": "..."}`）→ 发送验证码；5 分钟有效、60 秒重发间隔，未配置 SMTP 时降级日志输出验证码（仅限本地开发）。

**POST** `/auth/email-code/login`（`{"email": "...", "code": "..."}`）→ 免密登录；邮箱未注册时自动创建账号。

#### 第三方 OAuth 登录（google / github / qq）

**GET** `/auth/oauth/{provider}/authorize` → 302 跳转第三方授权页（state 防 CSRF，10 分钟有效）。

**GET** `/auth/oauth/{provider}/callback?code=&state=` → 后端换 token → 拉取用户信息 → 按 `provider + accountId` 查绑定；未绑定则按邮箱关联既有账号或新建账号并绑定 → 302 回前端 `frontendRedirect?token=..&refresh=..&guest=..`（失败时 `?error=..`）。

| 配置 | 环境变量 |
|---|---|
| Google | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` |
| GitHub | `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` |
| QQ | `QQ_APP_ID` / `QQ_APP_KEY` |
| 回调/前端地址 | `AUTH_OAUTH_BASE_URL` / `AUTH_OAUTH_FRONTEND_REDIRECT` |

未配置时 authorize 返回 400；`user_auth` 表（V12）保存第三方绑定。

#### 错误码

| 错误码 | 提示文案 |
|---|---|
| `AUTH_EMAIL_CODE_INVALID` | 验证码不正确或已过期。 |
| `AUTH_EMAIL_CODE_SEND_FAILED` | 验证码发送失败。 |
| `AUTH_EMAIL_CODE_TOO_FREQUENT` | 发送过于频繁。 |
| `AUTH_OAUTH_NOT_CONFIGURED` | 第三方登录未配置。 |
| `AUTH_OAUTH_EXCHANGE_FAILED` | 第三方登录失败。 |
| `AUTH_SMS_CODE_NOT_AVAILABLE` | 手机验证码登录即将上线。 |

| 字段 | 类型 | 必填 | 规则 |

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "id": "resume_1720000000001",
```

### 7.8 AI 点评简历

**POST** `/resumes/{id}/reviews`

对指定简历创建 AI 点评任务。接口返回任务标识，后台异步调用 LLM；未配置供应商时按降级策略生成占位结果。

#### 请求体

```json
{
  "jobDescription": "Java后端开发工程师，要求熟悉 Spring Boot、MySQL、Redis、消息队列...",
  "focusAreas": ["completeness", "match", "expression"]
}
```

#### 字段说明

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `jobDescription` | string | 否 | 目标岗位 JD，用于岗位匹配度评分 |
| `focusAreas` | string[] | 否 | 关注的点评维度，默认全部 |

#### 成功响应

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "reviewId": "review_1720000000001",
    "resumeId": "resume_1720000000001",
    "createdAt": "2026-07-04T10:00:00"
  }
}
```

#### 业务规则

1. 接口先写入 `pending` 任务并异步调用 LLM；通过 `GET /resumes/{id}/reviews/latest` 查询成功结果。
2. 后端将简历 `sections`、目标岗位、`scene` 等组装为 Prompt。
3. 点评结果保存到 `resume_review` 表，每份简历返回最近一次成功的点评记录。
4. 未配置供应商或调用失败时按设计回退到占位结果；每用户同时进行的 AI 任务最多 3 个。

#### 错误码

| 错误码 | 提示文案 |
|---|---|
| `RESUME_NOT_FOUND` | 简历不存在。 |
| `ACCESS_DENIED` | 无权访问该资源。 |
| `AI_PROVIDER_NOT_CONFIGURED` | 未配置 AI 供应商。 |
| `AI_MODEL_CALL_FAILED` | AI 模型调用失败。 |
| `AI_RESPONSE_PARSE_FAILED` | AI 点评结果解析失败。 |
| `AI_CONCURRENT_LIMIT_EXCEEDED` | 同时进行的 AI 任务过多。 |
| `RESUME_CONTENT_TOO_SHORT` | 简历内容过少，无法生成有效点评。 |

### 7.10 编辑器内 AI 写作

**POST** `/resumes/{id}/ai/write`

根据简历上下文对指定字段执行生成、润色、缩短、扩写或翻译，需 JWT 认证并校验简历归属。

#### 请求体

```json
{
  "sectionType": "project",
  "field": "description",
  "action": "polish",
  "originalText": "负责会员系统开发",
  "targetLang": "en"
}
```

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `sectionType` | string | 是 | 模块类型，最长 32 字符 |
| `field` | string | 是 | 服务端白名单字段，最长 64 字符 |
| `action` | string | 是 | `generate` / `polish` / `shorten` / `expand` / `translate` |
| `originalText` | string | 否 | 最长 2000 字符 |
| `targetLang` | string | 否 | `translate` 时必填，最长 16 字符 |

#### 成功响应

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "content": "主导会员系统的架构设计与开发"
  }
}
```

服务端从简历读取上下文，不信任客户端传入的原文；未配置 AI 供应商时返回占位结果。字段不在白名单或原文超长分别返回 `AI_WRITING_FIELD_INVALID`、`AI_WRITING_CONTENT_TOO_LONG`。

#### 按日配额

- 游客 3 次/天、登录用户 30 次/天（配置：`app.ai.daily-quota.guest/user`），同步与流式接口共享配额。
- 超限返回 `AI_DAILY_QUOTA_EXCEEDED`(6009)；游客身份由 JWT `guest` claim 判定。
- 计数持久化于 `ai_daily_quota` 表（V10 迁移），按「用户 × 功能 × 日期」唯一。

#### 流式写作

**POST** `/resumes/{id}/ai/write/stream`

请求体与同步接口相同，响应类型为 `text/event-stream`。事件约定如下：

| 事件 | data | 说明 |
|---|---|---|
| `delta` | 文本片段 | 按模型生成顺序返回的增量内容 |
| `done` | 空字符串 | 本次生成完成 |
| `error` | 错误信息 | 生成过程中发生错误；HTTP 状态保持 200，以保证已发送内容可被消费 |

Provider 不支持流式调用时，服务端将同步结果作为单个 `delta` 事件返回。

## 9. 头像模块 `/avatars`

> 本模块用于简历一寸照片生成。用户上传自拍照后，后端按指定背景色、风格、美颜选项生成标准一寸照片，再镶嵌到简历个人信息中。用户账号头像（`user.avatar_url`）不在本模块处理范围内。

### 9.1 上传自拍照

**POST** `/avatars/upload`

上传用户自拍照，作为一寸照片优化的原图。

#### Content-Type

`multipart/form-data`

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | file | 是 | JPG / PNG / WEBP，≤10MB，建议正面、光线充足的自拍照 |
| `resumeId` | string | 否 | 关联简历 ID，优化完成后可自动回填到该简历 |

#### 成功响应

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "id": "avatar_1720000000001",
    "sourceImageUrl": "/uploads/avatars/avatar_1720000000001_source.png",
    "fileName": "avatar.png"
  }
}
```

#### 业务规则

1. 校验文件格式（MIME 类型 + 扩展名）。
2. 校验文件大小 ≤10MB。
3. 重命名存储，避免原始文件名带来的安全风险。
4. 文件上传至 MinIO（或兼容 S3 的对象存储）Bucket `resume-avatars`，路径按 `{user_id}/avatars/{avatar_id}_source.{ext}` 组织。
5. 数据库与接口返回的是对象存储可访问 URL（开发环境可为相对路径或预签名 URL）。
6. 删除头像时同步清理 MinIO 上的原图与所有一寸照优化结果图。

#### 错误码

| 错误码 | 提示文案 |
|---|---|
| `AVATAR_FILE_EMPTY` | 请上传头像图片。 |
| `AVATAR_FORMAT_UNSUPPORTED` | 请上传 JPG、PNG 或 WEBP 格式图片。 |
| `AVATAR_FILE_TOO_LARGE` | 图片大小不能超过 10MB。 |

### 9.2 创建一寸照优化任务

根据用户上传的自拍照生成标准一寸照片，用于镶嵌到简历中。

#### 请求体

```json
{
  "sourceImageUrl": "/uploads/avatars/avatar_1720000000001_source.png",

  "brightenSkin": false
```

#### 字段说明

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `sourceImageUrl` | string | 是 | 非空，≤512 字符 |
| `resumeId` | string | 否 | 关联简历 ID，任务成功后可自动回填 |

| `enhanceQuality` | boolean | 否 | 是否高清增强，默认 false |
| `removeBackground` | boolean | 否 | 是否智能抠图换底，默认 false |

#### PRD 选项与 API 字段映射

`docs/需求PRD-v1.md` §7.4.4 中的 10 个优化选项映射到本接口参数如下：

| PRD 选项 | 中文 | 对应 API 字段/参数 |
|---|---|---|
| 白底证件照 | 背景色 | `backgroundType = white` |
| 蓝底证件照 | 背景色 | `backgroundType = blue` |

| 自然清爽头像 | 风格 | `style = natural` |
| 高清修复 | 画质增强 | `enhanceQuality = true` |
| 去除杂乱背景 | 抠图换底 | `removeBackground = true` |
| 提亮肤色 | 美颜磨皮 | `brightenSkin = true` |

```json
}
```

1. P0 不接入真实 AI 模型。
2. 后端根据请求参数对原图做简单处理（如缩放、居中裁剪）或直接复制原图作为一寸照占位结果。

| 错误码 | 提示文案 |
|---|---|
| `AVATAR_SOURCE_NOT_FOUND` | 原图不存在或已删除。 |
| `AVATAR_BACKGROUND_TYPE_INVALID` | 背景类型不正确。 |
| `AVATAR_STYLE_INVALID` | 照片风格不正确。 |

1. 仅允许删除 `is_builtin = 0` 的模板。
2. 删除为逻辑删除，设置 `deleted = 1`；`status` 保持原业务状态不变。
3. 已引用该模板的简历不受影响，但切换模板时不可再选回该模板。

#### 错误码

| 错误码 | 提示文案 |
|---|---|
| `TEMPLATE_NOT_FOUND` | 模板不存在。 |
| `TEMPLATE_BUILTIN_PROTECTED` | 系统内置模板不可删除。 |

## 11. PDF 模块 `/pdf`

### 11.1 创建 PDF 导出任务

**POST** `/pdf/export`

#### 请求体

```json
{
  "resumeId": "resume_1720000000001",
  "templateId": "template_classic_single"
}
```

#### 字段说明

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `resumeId` | string | 是 | 简历 ID |
| `templateId` | string | 否 | 模板 ID；为空时使用简历当前关联的模板，传入则覆盖本次导出所使用的模板但不修改简历 |

#### 成功响应

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "taskId": "pdf_task_1720000000001",
    "status": "pending"
  }
}
```

#### 业务规则

1. `templateId` 为空时使用简历当前关联的模板；传入则仅覆盖本次导出渲染所用的模板，不修改 `resume.template_id`。
2. 导出前校验：简历存在、用户有权限、简历中至少填写姓名和联系方式（一个联系方式即可）。
3. 后端读取简历和模板配置，渲染完整 HTML。
4. 调用 Playwright 将 HTML 转为 A4 PDF。
5. 文件命名规则：
   - 有姓名和目标岗位：`{姓名}_{目标岗位}_简历.pdf`
   - 有姓名无目标岗位：`{姓名}_简历.pdf`
   - 无姓名：`我的简历_yyyyMMdd.pdf`（例如 `我的简历_20260707.pdf`）

#### 错误码

| 错误码 | 提示文案 |
|---|---|
| `RESUME_NOT_FOUND` | 简历不存在。 |
| `ACCESS_DENIED` | 无权访问该资源。 |
| `PDF_EXPORT_NAME_REQUIRED` | 建议填写姓名，便于生成正式简历。 |
| `PDF_EXPORT_CONTACT_REQUIRED` | 简历中至少需要填写手机号或邮箱。 |
| `TEMPLATE_NOT_FOUND` | 模板不存在。 |

## 13. 幂等性规范

对于创建类接口（注册、创建简历、创建头像优化任务、创建 PDF 任务），建议前端在请求头中携带：

```http
Idempotency-Key: {uuid}
```

后端对同一 `Idempotency-Key` 在有效期内返回同一结果，避免重复创建。

## 14. 安全规范

1. **鉴权**：所有业务接口必须校验 JWT，游客 Token 同样有效。
2. **数据隔离**：所有查询必须带上 `user_id` 校验，禁止访问其他用户资源。
3. **文件安全**：上传文件校验 MIME 类型和扩展名，重命名存储，禁止可执行文件。
4. **XSS 防护**：简历内容输出时进行 HTML 转义，PDF 渲染使用安全模板。
5. **敏感字段脱敏**：用户列表/详情中手机号、邮箱按需脱敏展示。
